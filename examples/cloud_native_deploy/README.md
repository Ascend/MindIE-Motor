# Cloud-Native Deploy

This directory provides a cloud-native deploy flow for `examples/deployer/deploy.py`.

It is intended for platform-triggered deployment and does not depend on logging into a host machine or using host-local files.

## Why this exists

The original deploy flow assumes an operator logs into a Kubernetes node and runs `examples/deployer/deploy.py` manually with local config files.

That works for manual verification, but it becomes difficult to operate in a real cloud platform environment:

- Multi-tenant clusters usually run multiple inference services at the same time and isolate them by namespace.
- Platform users should not need shell access to cluster nodes.
- Deployment requests are usually submitted through platform APIs or control planes, not by running scripts on a host.
- Delivery artifacts should be immutable container images and Kubernetes manifests, not host-local generated files.
- Scale and cleanup operations should also be expressed as Kubernetes Jobs so that the platform can audit, retry, and observe them.

This directory packages the existing deploy logic into a container-friendly form so that a cloud platform only needs to:

1. Prepare a ConfigMap that contains `user_config.json` and `env.json`.
2. Launch a Kubernetes Job for deploy, scale, or cleanup.

The deploy implementation itself is still the existing `examples/deployer/deploy.py`, which keeps behavior aligned with the current manual workflow while making the entrypoint cloud-native.

## Build image

From repo root:

```bash
docker build -f examples/cloud_native_deploy/Dockerfile -t mindie-pymotor-deployer:latest .
```

Or use the root Makefile:

```bash
make buildx-cloud-native-deployer TAG=latest
```

## Prepare config

Edit `k8s/configmap-user-config.yaml` and paste both your `user_config.json` and `env.json`.

Optional:

- Set `motor_deploy_config.scheduling_queue` to control the Volcano queue.
- Set `motor_deploy_config.coordinator_service_name` to override the external inference Service name.
- Set `motor_deploy_config.coordinator_infer_node_port` to override the inference Service NodePort. Use `"-"` for Kubernetes allocation; omitting it keeps the `nodePort` configured in the template, which currently defaults to `31015`.
- Set `motor_deploy_config.prefill_node_selector` and `motor_deploy_config.decode_node_selector` to control Prefill/Decode node placement separately.
- Set `motor_deploy_config.controller_node_selector` and `motor_deploy_config.coordinator_node_selector` to control Controller/Coordinator placement separately.
- Set `motor_deploy_config.kv_pool_node_selector` and `motor_deploy_config.kv_conductor_node_selector` to control KV Pool/KV Conductor placement separately.

## Deploy with Helm

The community `helm/` chart creates the ConfigMap, ServiceAccount, RBAC, and deploy/scale/cleanup Jobs. Runtime resources are still generated by `examples/deployer/deploy.py` inside the Job.

Copy and edit the default values, including both the deployer image and the Motor runtime image:

```bash
cp examples/cloud_native_deploy/helm/values.yaml /tmp/pymotor-values.yaml

helm upgrade --install pymotor examples/cloud_native_deploy/helm \
  --namespace mindie \
  --create-namespace \
  --values /tmp/pymotor-values.yaml \
  --set operation=deploy
```

Use `operation=scale` after changing the instance counts. To remove runtime resources, run `operation=cleanup` before `helm uninstall`.

See [the Helm chart README](helm/README.md) for details.

## Apply RBAC and run

```bash
kubectl apply -f examples/cloud_native_deploy/k8s/serviceaccount.yaml
kubectl apply -f examples/cloud_native_deploy/k8s/clusterrole.yaml
kubectl apply -f examples/cloud_native_deploy/k8s/clusterrolebinding.yaml
kubectl apply -f examples/cloud_native_deploy/k8s/configmap-user-config.yaml
kubectl apply -f examples/cloud_native_deploy/k8s/job.yaml
```

Check logs:

```bash
kubectl logs job/mindie-pymotor-deploy -n mindie
```

## Scale

Update `p_instances_num` and/or `d_instances_num` in `k8s/configmap-user-config.yaml`, re-apply the ConfigMap, then run:

```bash
kubectl apply -f examples/cloud_native_deploy/k8s/scale-job.yaml
kubectl logs job/mindie-pymotor-scale -n mindie
```

## Cleanup

The cleanup Job only requires a target namespace.

```bash
kubectl apply -f examples/cloud_native_deploy/k8s/cleanup-job.yaml
kubectl logs job/mindie-pymotor-cleanup -n mindie
```
