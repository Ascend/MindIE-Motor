## Feature Description

The Controller process entry point is `motor/controller/main.py`. At startup, `ControllerConfig` is loaded (from the file specified by `--config`, or from a JSON parsed from environment variables when not specified, consistent with the behavior of `ControllerConfig.from_json`), and then the following modules are initialized in sequence (see `init_all_modules`):

| Module | Source Code | Function |
|--------|------|----------|
| `InstanceAssembler` | `motor/controller/core/instance_assembler.py` | Processes registration/re-registration reported by the Node Manager and assembles instances. |
| `EventPusher` | `motor/controller/core/event_pusher.py` | Pushes events as an observer of `InstanceManager`. |
| `FaultManager` | `motor/controller/fault_tolerance/fault_manager.py` | Loaded only when `fault_tolerance_config.enable_fault_tolerance` is true; can be attached to `InstanceManager` and `start()`. |
| `InstanceManager` | `motor/controller/core/instance_manager.py` | Maintains persistent data such as instance dictionaries, heartbeats, statuses, and etcd (as outlined in the class docstring). |
| `Observability` | `motor/controller/observability/observability.py` | Loaded only when `observability_config.observability_enable` is true |
| `ControllerAPI` | `motor/controller/api_server/controller_api.py`. | Starts FastAPI/uvicorn in a separate thread, providing management-plane HTTP APIs externally. |

If master/standby is enabled (`standby_config.enable_master_standby`), only `ControllerAPI` is started initially, and the remaining business modules are started later when `StandbyManager` invokes the `on_become_master` callback ; when switching to standby, `on_become_standby` stops all modules except `ControllerAPI` (see comments in `main.py`).

Configuration hot reload: When `config.config_path` exists and the file is on disk, `ConfigWatcher` is started. After reloading, `on_config_updated` is called, which can execute `update_config` for each module and start or stop `FaultManager` as the fault switch changes.

## Environment Setup

- The required JSON configuration must comply with the field definitions of `ControllerConfig`; see `motor/config/controller.py`.

- Mount paths, environment variables, and other items related to cluster deployment must be consistent with the startup scripts and ConfigMap generated by `examples/deployer`. For deployment steps, see [Environment Setup](../environment_preparation.md) and [Configuration Reference](../service_deployment/config_reference.md).

## Configuration Description

The corresponding block in the user-side overall configuration is **`motor_controller_config`** (the key names in the documentation are based on `config_reference.md`). Commonly used items in the code include:

- **API**: `api_config.controller_api_host`, `controller_api_port` (default `1026`), `observability_api_port` (default `1027`), etc. See `ApiConfig` in `motor/config/controller.py`.

- **TLS**: `mgmt_tls_config`, `observability_tls_config`, etc. `ControllerAPI` starts the main API using HTTPS when `mgmt_tls_config.enable_tls` is true.

- **Master/Standby**: `standby_config.enable_master_standby`.

- **Observability**: `observability_config.observability_enable` controls whether HTTP capabilities such as inventory, metrics, and alarms are exposed on a separate observability app (see `_create_observability_app` and the decorator `observability_enabled_required`).

For the complete field table, refer to [Configuration Reference: motor_controller_config](../service_deployment/config_reference.md).

## External HTTP Routes (Main API)

The routes registered by `ControllerAPI._create_app` include (methods are subject to the code):

| Method | Path | Processing Logic Key Points |
|------|------|----------------|
| `POST` | `/controller/heartbeat` | Parses `HeartbeatMsg`, `InstanceManager().handle_heartbeat`. |
| `POST` | `/controller/register` | Parses `RegisterMsg`, `InstanceAssembler().register`. |
| `POST` | `/controller/reregister` | Parses `ReregisterMsg`, `InstanceAssembler().reregister`. |
| `POST` | `/controller/terminate_instance` | Parses `TerminateInstanceMsg`, sends stop commands to each Node Manager, etc. |
| `GET` | `/startup`, `/readiness`, `/liveness` | Probe-type interfaces (see the corresponding handlers in the same file for implementation). |
| `POST` | `/observability/add_alarm` | Reports alarm records. |

There is also a separate **Observability** FastAPI app (port `observability_api_port`), which provides routes such as inventory, metrics, and alarms when `observability_enable` is true; when not enabled, the related interfaces return errors like "Observability is not enabled." (see `observability_enabled_required`).

### Observability App Routes

| Method | Path | Description |
|------|------|------|
| `GET` | `/observability/inventory` | Gets service inventory information. |
| `GET` | `/observability/metrics` | Gets monitoring metrics, and supports the `type` parameter to switch metric granularity (see below). |
| `GET` | `/observability/alarms` | Gets alarm information, and supports the `source_id` query parameter for filtering. |

#### GET /observability/metrics

> [!NOTE] Route proxy description
> The Controller's `/observability/metrics` is a route proxy for the Coordinator's `/metrics` and does not perform data processing. All metric aggregation, label injection, and Prometheus format serialization are completed on the Coordinator side. The Controller only forwards the request to the Coordinator's `GET /metrics?type={type}&role={role}` and returns the response.

**Request Parameters**

| Parameter | Type | Required/Optional | Default | Description |
|--------|------|------|--------|------|
| `type` | string | Optional | `full` | Metric type: `full` (full aggregation), `instance` (instance-level), `role` (aggregated by role) |
| `role` | string | Optional | None | When `type=role`, specifies the role name: `prefill` or `decode`. Returns a dictionary of aggregated metrics for all roles when not specified |

**`type` Value Description**

| Value | Content-Type | Return Format | Description |
|------|-------------|----------|------|
| `full` | `text/plain` | Prometheus text | Full aggregation metric (default), Prometheus text after Coordinator aggregates all instances/endpoints |
| `instance` | `text/plain` | Prometheus text | Instance-level metric, Coordinator has injected `instance_id` and `role` labels |
| `role` (role specified) | `text/plain` | Prometheus text | Aggregated metric for the specified role, Coordinator has injected `role` label |
| `role` (role not specified) | `text/plain` | Prometheus text | Aggregated metrics for all roles concatenated into a single Prometheus text |

**Usage Example**

```bash
# Full aggregation metric (default)
curl -X GET "http://{ControllerIP}:{observability_api_port}/observability/metrics"
curl -X GET "http://{ControllerIP}:{observability_api_port}/observability/metrics?type=full"

# Instance-level metrics
curl -X GET "http://{ControllerIP}:{observability_api_port}/observability/metrics?type=instance"

# Aggregated metrics for all roles
curl -X GET "http://{ControllerIP}:{observability_api_port}/observability/metrics?type=role"

# Prefill role only
curl -X GET "http://{ControllerIP}:{observability_api_port}/observability/metrics?type=role&role=prefill"

# Decode role only
curl -X GET "http://{ControllerIP}:{observability_api_port}/observability/metrics?type=role&role=decode"
```

## Usage Examples

```bash
# Specify the configuration file (consistent with argparse in main.py)
python -m motor.controller.main --config /path/to/controller_config.json
```

In non-interactive environments, the main loop may block on `select`/`wait`; exit can be done via SIGINT/SIGTERM (`signal_handler`) or interactive input `stop`.

## Errors and Logs

- The API layer returns JSON with an `"error"` field description for invalid bodies, such as `"Invalid HeartbeatMsg format"`, `"Instance not found"`, etc. (see implementations like `_heartbeat`, `_register`).

- Controller-side logs use `motor.common.logger`; the specific disk path is determined by `LoggingConfig`, see the log-related configuration in `motor_controller_config`.
