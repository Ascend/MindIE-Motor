# [2026-10-16] 实例刷新遇到非法 role 时部分实例已注册

- **现象 (Symptom)**：一次 `POST /instances/refresh`（`event=add`）提交多个实例时，若前面的实例合法、后面的实例 `role` 非法（如 `router`），接口返回 `400`（`'router' is not a valid PDRole`），但**前面的实例已经进入可用池**：`GET /instances` 能查到它，调用方却因为收到 400 认为自己没注册成功。日志顺序为 `Added instance ID 4097 (role: prefill, ...) to available pool successfully` → `AUDIT: ... result=failed: 400: 'router' is not a valid PDRole`。`event=resume` 的同型场景是：第一条合法实例已被放回可用池，第二条非法 role 报 400，且它已从 paused 池删除，之后 `GET /instances` 里彻底看不到这条实例。
- **根因 (Root cause)**：`InstanceManager._validate_refresh_instances`（`motor/coordinator/domain/instance_manager.py`）只校验重复 ID 与身份冲突，不校验 `role`；`role` 直到 `_add_instances` → `_add_instance_to_available_pool` → `_role_to_pdrole`（`PDRole(role)`）才被解析，而该函数是在**逐条 apply 的过程中**调用的，此时同一请求中排在前面的实例已写入角色池、`_available_pool` 与 endpoint 缓存。异常向上冒泡到 `management_server` 的 `except ValueError` 分支变成 400，于是「已生效但报失败」。`event=resume` 更严重：`_resume_instances` 先 `del self._paused_pool[id]` 再调用 `_add_instance_to_available_pool`，role 解析失败时该实例既不在 available、也不在 paused，等于从所有池里凭空消失，而接口同样只回 400。
- **为什么会写出 (Why)**：把 role 当成「插入时才需要的字段」，只在真正使用它的函数里校验（fail-where-used），忽略了 `/instances/refresh` 是批处理接口——校验一旦落在 apply 中间，接口就不再原子，而 400 的语义恰恰是「整批没生效」。Controller 从 K8s 标签构造 role、External Deployer 协议在 `ExternalInsEventMsg.to_internal()` 里已提前校验 role，只有 Controller 形状（完整 `InsEventMsg`）这一条路径漏了。
- **修复 (Fix)**：`_validate_refresh_instances` 在 ADD / SET / RESUME 分支之前统一调用 `_resolve_refresh_role(instance)`（`_role_to_pdrole` + 角色池成员校验），非法 role 在任何池变更前抛 `ValueError`（仍由既有 400 分支返回），使请求对 role 合法性变成 all-or-nothing；报错带上 `instance.id` 与原始值，批量提交时能定位到具体实例。非 `str` 的 role（`_role_to_pdrole` 会原样返回，例如内部调用方传 `None`）由成员校验拦下，不再走到 `_add_instance_to_available_pool` 里只打一条 `Unknown role` 日志就返回 200。DEL / PAUSE 不校验 role（不写角色池；role 只参与 DEL 身份比较）。`_resume_instances` 改为 `pop` 后在回插失败时把条目放回 paused 池，保证失败路径不会丢实例。
- **测试拦截 (Test interception)**：`tests/coordinator/api_server/test_management_server_instances.py` 用真实 HTTP 接口 + 真实 `InstanceManager` 覆盖三条事件路径：`test_rejected_payload_is_not_partially_applied`（add：1 合法 + 1 非法 role → 400 且可用池为空）、`test_set_with_invalid_role_is_not_partially_applied`（set 走 `_apply_set_diff` → `_add_instances`，与 add 不是同一条路径）、`test_resume_with_invalid_role_keeps_instance_paused`（pause 后提交 1 合法 + 1 非法 role 的 resume → 400，两个实例都仍在 paused 池，`GET /instances` 仍能看到它们）、`test_rejection_names_the_offending_instance`（400 详情含实例 ID）、`test_unsupported_role_value_is_rejected_before_apply`（`model_construct` 出的非 `str` role 直接抛 `ValueError`，不再静默 200）。
- **场景 (Scenario)**：任何以完整 `InsEventMsg` 形状（实例带 `job_name`、`endpoints` 为 dict）调用管理接口、且一次提交多个实例的客户端——例如引擎 sidecar 直接复用 Patio/`register.py` 的报文，或第三方集成脚本；role 拼写错误、传 `P`/`D` 简写、传历史遗留角色名时触发。官方 `register.py` CLI 只从 `--prefill`/`--decode` 生成 role，不会触发。
