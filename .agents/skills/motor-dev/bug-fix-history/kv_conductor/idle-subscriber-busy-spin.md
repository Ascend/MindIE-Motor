# 空闲订阅器忙轮询

- **现象**：未收到 KV 事件时订阅线程持续占用 CPU。
- **根因**：设置接收超时后仍使用 DONTWAIT，EAGAIN 分支立即进入下一轮。
- **为什么会写出**：误以为非阻塞读取仍会遵守接收超时。
- **修复**：使用完整 multipart 阻塞接收，沿用 500 ms 超时检查取消。
- **测试拦截**：Linux 线程 CPU/取消回归在旧接收逻辑失败；真实 XPUB/SUB 验证完整消息到达后唤醒。
- **场景**：引擎或存储池订阅空闲，尤其多个订阅并存。
- **关键词**：ZMQ, DONTWAIT, EAGAIN, idle CPU, cancellation。
