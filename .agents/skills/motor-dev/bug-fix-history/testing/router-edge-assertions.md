# [2026-11-10] Router 边缘测试未锁住失败后的输出与精确边界

- **现象 (Symptom)**：收尾帧写失败用例仅检查 HTTP 200，不能发现额外错误 SSE 或重试；错误预览仅检查前缀，遗漏非法 UTF-8 替换内容及截断等值边界。
- **根因 (Root cause)**：`test_stream_response.py` 的模拟发送只拒绝第一次收尾帧，且未核对完整发送序列；`test_upstream_error.py` 缺少精确输出断言。
- **为什么会写出 (Why)**：验证了请求曾经成功开始，却没有验证失败后还允许出现哪些事件；预览测试混淆了“不抛异常”和“输出正确”。
- **修复 (Fix)**：记录每次发送尝试并持续拒绝收尾帧，断言仅有启动、数据、收尾三帧；精确检查两个 U+FFFD 替换字符及恰好达到预览上限时没有省略号。原生 abort 模拟按同文件约定规范化路径，对未知业务路径报错，独立断言默认配置下的 1 秒停止超时。
- **测试拦截 (Test interception)**：经运行时故障注入确认，原用例会放过收尾重试、丢弃替换字符、等值边界错误截断，修正后均失败；abort 路径带尾斜杠时，原模拟未识别停止请求，修正后四类失败用例均正常验证。
- **场景 (Scenario)**：通过 ASGI 发送已提交响应、打印上游错误预览，或模拟原生引擎 best-effort abort 失败。
- **关键词 (Keywords)**：router, terminal frame, SSE, UTF-8, abort_request
